ポーカーチップアプリ 総合設計書 (完全版)

1. システム構成・技術スタック

  • フロントエンド: Flutter, Riverpod (状態管理)
  • バックエンド・DB: Supabase (PostgreSQL, Supabase Realtime, Supabase Presence)
  • ホスティング: Vercel
  • マネタイズ (広告): Google Mobile Ads SDK (動画リワード広告)

2. 基本ルールと進行管理

  • 現実とアプリの役割分担: 物理的なトランプを使用し、アプリは純粋にチップの計算と進行（ターン）管理のみを行う。
  • ディーラーレス進行: ディーラー権限は存在せず、全員のベット額が揃ったタイミングをSupabase Realtimeで検知し、全プレイヤーの画面に「カードをめくってください」等のシステムメッセージを一斉表示してフェーズを進行させる。
  • オールイン演出: オールインが発動した際は、全画面にアニメーションエフェクトを表示する。

3. 権限とフェイルセーフ仕様

  • ホスト権限: 部屋を作成したプレイヤーがホストとなる。ホスト自身が切断された場合、権限の自動移譲は行わず、復帰するまで全員で待機する。
  • キック（退室）機能とデッドマネー: ホストは他プレイヤーをキックできる。キックされたプレイヤーがそのハンド中に賭けていたチップは返還されず、「デッドマネー」としてポットに残る。
  • Undo（一手戻る）機能: 進行の時系列の矛盾を防ぐため、Undo用の「×」ボタンは一番最後（最新）にアクションしたプレイヤーのバッジにのみホスト画面で表示される。直前の1手のみ取り消しが可能。

4. 資産管理と借金（10,000ドル単位）

  • 初期資金: 各プレイヤー $10,000 からスタート。
  • ゼロサム原則: 全プレイヤーの「純資産（Net Asset）」の合計は、常に (参加人数) × 10,000 になるように表示する。
  • 表示の分離: プレイヤーの資金は「純資産」と「手持ちチップ（Playable Chips）」に分けて表示する。
  • 借金のタイミング: テーブルステークス（プレイ中の有効スタック変動）の矛盾を防ぐため、10,000ドル単位の借金ボタンは、ゲーム中（ハンド進行中）は非表示とし、ハンドが終了した待機中のみ使用可能とする。借金すると手持ちチップが +10,000 されるが、純資産の評価は変動しない（負債として相殺されるため）。

5. ハートシステムと動画広告

  • 基本仕様: プレイヤーごとに独立したハート（最大5）を持つ。1ゲーム（ハンド）ごとに1減少する。
  • あいことば: ホーム画面で正しい「あいことば」を入力すると、DB上でフラグが立ち、ハートが減少しない（広告非表示）状態となる。
  • 動画広告による回復: ハートが0になったプレイヤーは、動画リワード広告を視聴することでハートを最大まで回復する。
  • 他プレイヤーの待機ロック: 誰かが広告を視聴している間、他の全プレイヤーの画面には「〇〇がハートを回復しています」と表示され、進行がロックされる。
  • 30秒タイムアウト機能 (切断対策): 広告視聴中のプレイヤーが通信切断や強制終了により復帰しない場合による「進行不能（ソフトロック）」を防ぐため、30秒経過で自動的にタイムアウトとなり、当該プレイヤーは強制キック扱いとしてロックが解除される。

6. データベース設計 (Supabase PostgreSQL)

テーブル名主要カラム説明
rooms id, room_code, host_player_id, pot, highest_bet, current_phase, current_turn_player_id 部屋の状態と進行フェーズの管理
players id, room_id, name, hearts, is_ad_free, borrow_count, current_bet, status プレイヤーの状態。borrow_count (借金回数) を基に純資産を計算
action_logs id, room_id, player_id, action_type, amount, created_at Undo機能を実現するための直近アクションの履歴記録
